## 1. codex 的合約到底怎麼寫的

> gate 2：**連續 20 次「非命中」嘗試所造成的複利帳戶跌幅 ≤ 20.0%**。

兩個定義是關鍵，而我兩個都沒照做：

- **一次「嘗試」＝一次已執行的換股（買進到賣出）**，不是一次虧損。
- **「非命中」＝沒有達到飆股門檻的嘗試**——**這明確包含賺錢的嘗試。**
  一筆 +3% 就出場的交易是「非命中」，但它是**正的**，它會抵銷前後的小賠。

擁有者描述的「3 次小賠、1 次小賺、5 次小賠、3 次小賺」正是這條門檻要衡量的東西，
而我的實作把那 4 次小賺**刪掉**之後才開始算。

## 2. 我實際寫了什麼

四張卡（`20260906-five-slot-confirmation`、`20260906-absolute-entry-bar`、
`20260906-equal-risk-sizing`、`20260906-three-slot-equal-risk`）都用同一段：

```python
losses = [pnl for pnl in round_trips(summary) if pnl < 0]      # 先把賺的全部丟掉
worst  = max(abs(sum(losses[i : i + 20]))) / start_equity      # 再除以期初本金
```

**錯誤一：先過濾再取窗口。** 這 20 筆虧損可能橫跨 40、60 次嘗試，中間所有的獲利被移除。
它衡量的是「最壞的 20 次虧損」，不是「最壞的 20 次嘗試」。

**錯誤二：分母是期初本金。** 這個帳本在訓練期會從 200 萬長到 800 萬以上。
一筆發生在帳戶 600 萬時的 30 萬虧損，真實代價是 5%，
用 200 萬當分母會被記成 **15%**——**放大三倍。**

兩個錯誤方向一致，所以published 的數字**只會偏大，不會偏小**。

## 3. 驗證：配對本身是對的

一張更正報告如果自己的算術沒被驗證過，它只是換一個沒有根據的數字。
所以 `streak.py` 先做對帳，**十五個帳本、每個四項，全部與引擎自己的指標完全相等**：

| 對帳項目             | 結果                         |
| -------------------- | ---------------------------- |
| `closed_trade_count` | 15/15 完全相等               |
| `win_count`          | 15/15 完全相等               |
| `gross_profit`       | 15/15 完全相等（到小數兩位） |
| `gross_loss`         | 15/15 完全相等（到小數兩位） |

**這裡有一個定義上的細節，值得記下來。** 引擎的 `gross_profit`／`gross_loss`
**只算買賣兩腳，不含配息**；而連賠這個量測**要含配息**，因為配息是真的進到帳戶的現金，
而擁有者問的是帳戶。所以程式同時保留兩欄：`pnl_ex_dividend` 用來對帳，`pnl` 用來算連賠。
封閉交易裡的配息現金在 5.8 萬到 32.4 萬之間（2026-09-08 修好漏算後的數字，見第 10 節）。

**這條對帳一開始是失敗的**——我原本拿含配息的數字去對引擎不含配息的指標，
`win_count` 差 1~5 筆、`gross_profit` 一律偏高。查清楚之後才確定差異就是配息，不是配對錯誤。
（這條線上已經被配對咬過一次：用「價格 × 股數」配對曾經默默漏掉 35 筆 DIVIDEND 事件。）

## 4.1 爭議點本身：連賠到底跟檔數有多大關係

**這一節必須逐「直行」讀。** 拿 `k3/er15` 去比 `k5/er30` 是把兩個軸混在一起，
會製造出一個其實是出場名次在動的假斷點——**我原本的比較就犯了這個錯。**

訓練期，NT$2M，格式為「已發表 → 更正後」，`*` 代表通過 codex 的 20% 上限：

| k   | er15                  | er30                  | er45                  |
| --- | --------------------- | --------------------- | --------------------- |
| 3   | 52.7% → **21.2%**     | 61.7% → 27.8%         | 62.1% → 35.3%         |
| 4   | 38.6% → 24.4%         | 45.8% → 25.4%         | 48.4% → 31.8%         |
| 5   | 31.5% → **21.3%**     | 38.2% → 23.8%         | 41.0% → 26.1%         |

**三件事同時為真，全部都要說：**

**一、我當初的「算術」印象有真實來源。** 已發表的數字在**三個直行裡全部嚴格單調遞減**，
一格都沒有例外。面對那樣一張表，「連賠是 1/檔數」是一個合理的推論。
**它錯在數字本身是壞的，不在推論方式。**

**二、更正後這個關係變得又弱又不規則。** er15 欄的級距從 **3.3 倍（52.7/16.2）
縮到 1.5 倍（21.2/13.9）**，而且**單調性在 er15 欄斷掉**——k3 的 21.2% 比 k4 的 24.4% 更好，
也跟 k5 的 21.3% 幾乎相同。er30 與 er45 兩欄仍然單調。
**這個斷點在兩種排序下都成立**（進場順序：k3 21.2%、k4 24.9%、k5 24.2%），
所以它不是排序造成的假象。

**三、但在訓練期，通過 20% 上限的確實只有 k=7 與 k=10，六格全過；k=3/4/5 九格全不過。**
**這是我的說法裡唯一活下來的部分**，而且它比原本弱得多：
k3/er15 差 **1.2pp**、k5/er15 差 **1.3pp**，不是原本看起來的 32pp 與 11pp。

**決定這件事的是驗證期。** 同一個 k5 組態在驗證期是 **8.9%**，
比訓練期的任何 k=10 格子都好。**如果連賠真的是 1/檔數的結構性算術，
那不可能發生。** 所以正確的結論是：
**連賠主要由行情決定，檔數只是次要因素**——
這與 09-05 學到的「週轉率 = 規則 × 行情」是同一個型態，
而那次的教訓正是**不要拿訓練期校準出來的數字當門檻**。

## 5. 誤差分解：兩個錯誤各自貢獻多少

**其實是三個可分離的步驟，不是兩個。** 「丟掉獲利」與「用相加取代複利」是兩件不同的事，
如果只切兩刀，前者會把後者的效果吃進去。下表三欄互不重疊：

| 帳本               | 已發表 |  ＝ 正確 | ＋ 丟掉獲利 | ＋ 相加而非複利 | ＋ 期初本金分母 |
| ------------------ | -----: | -------: | ----------: | --------------: | --------------: |
| k5 er30 訓練期     |  38.2% |    23.8% |      +3.8pp |          +4.3pp |          +6.3pp |
| **k5 er30 驗證期** |  33.1% | **8.9%** |  **+8.8pp** |          +1.7pp |     **+13.7pp** |
| k3 er15 訓練期     |  52.7% |    21.2% |      +8.5pp |          +5.1pp |         +17.9pp |
| k7 er30 訓練期     |  26.1% |    17.3% |      +0.9pp |          +1.7pp |          +6.3pp |
| k10 er45 訓練期    |  22.6% |    16.1% |      +1.3pp |          +1.6pp |          +3.7pp |
| k3 等風險 0.013    |  42.5% |    26.2% |     +10.6pp |          +8.1pp |      **−2.5pp** |
| k3 等風險 0.015    |  47.6% |    36.5% |      +7.5pp |         +12.9pp |      **−9.3pp** |

**三個觀察值得記住：**

**一、最大的單一元凶是分母，不是丟掉獲利。** 十五個帳本裡有九個是分母那一欄最大。
k5 驗證期的帳戶成長最猛，所以「期初本金當分母」在那裡最致命
（+13.7pp，比錯誤本身的 8.9% 還大）。
**這代表這個錯誤不是均勻的偏差，它會系統性地懲罰最成功的組態。**

**二、分母那一項在賠錢的帳本上是負的。** k3 等風險 0.015 是 −9.3pp——
因為那個組態的帳戶掉到期初本金以下，用期初本金當分母反而**低估**了痛苦。
**所以這個錯誤的方向取決於帳本賺賠，它不是一個可以事後用單一係數修正的偏差。**

**三、「丟掉獲利」單獨看比想像中小。** 在 k5 訓練期只有 3.8pp（不是切兩刀時看到的 8.1pp），
差額其實來自「相加而非複利」。**這一點是複檢時被指出來的，我原本的分解把兩件事混在同一欄。**

正確的區間是 **16.7%~24.3%**，而**最嚴的那一格（收縮 ≤ 0.80）其實通過了 codex 的安全上限**。
**它失敗的真正原因是報酬崩掉（233% → 62%），不是安全性。**
這是一個比原本更清楚的結論：**「行情不好就空手」的這個版本，不是不夠安全，是太貴。**

### 6.4 `20260906-five-slot-confirmation`（gate D2）

## 8. 這張卡不能推論的事

**「連續 20 次嘗試」的複利算法本身是一個建模選擇，不是唯一解。**
我把每一次嘗試的效果定義為 `損益 ÷ 進場當日的帳戶淨值`，再把 20 個連乘。
部位是重疊的（同時持有 3~10 檔），所以「連續 20 次嘗試」在時間軸上不是一個乾淨的區間，
**沒有任何一段權益曲線可以直接對照這個數字。** 另一個同樣合理的選擇是用**出場當日**的淨值當分母。
**codex 的合約沒有指定這一點**，所以如果她的實作選了另一邊，數字會有差異——
這正是應該由她獨立重算來交叉檢驗的地方。

**這張卡沒有跑任何回測**，所有數字都從已存在的 `runs/*.json` 重算。
**沒有開任何新的驗證期視窗**；`k3/er15` 與 `k7/er30` 的驗證期仍然是乾淨未讀的。

**k5 驗證期的 8.9% 不是一個「被驗證的優點」。**
那個視窗是在 `20260906-five-slot-baseline` 已經被打開過的，
所以它是已知資訊，不是樣本外證據。

## 9. 方法教訓

**一個門檻如果是別人合約裡的定義，實作前要先把定義逐字讀完，而不是照字面印象寫。**
「連續 20 次非命中」被我讀成「連續 20 次虧損」，中間差的就是「非命中包含賺錢的嘗試」這一句。
這個錯誤在四張卡上重複了四次，因為第一次寫完之後就被複製貼上，**沒有任何一張卡重新檢查過它。**

**擁有者用常識抓到了一個我用程式沒抓到的錯誤。**
他沒有看程式碼，他只是想像了 20 次嘗試實際上長什麼樣子，然後發現我的數字不合理。
**這類反對應該被當成 bug report 處理，而不是當成需要解釋的誤會。**

## 10. 這張卡自己的更正（2026-09-08）

另一條線在 2026-09-08 加入了共用的量測層（`research_core/`、`docs/en/research-foundation.md`）。
拿它去對這張卡，找到**我自己的兩個缺陷**。兩個都已修好，**兩個都不影響任何已發表的數字。**

**一、賣出之後才入帳的股利被靜默丟掉。** 原本的配對只在部位還開著時才把股利加進去：

```python
elif code in open_cost:          # 只有還持有時才會進到這裡
    extra[code] = extra.get(code, 0.0) + total
```

除息在賣出之前、實際配發在賣出之後的那些股利，會掉出所有分支而消失——
**每個帳本 2 到 10 筆，k3/er15 是 8 筆裡漏掉 4 筆、共 NT$160,570。**
對帳查不到它，因為引擎的 `gross_profit`／`gross_loss` 本來就不含股利。
**是另一條線嚴格的帳本（`replay_ledger` 直接以「DIVIDEND requires a current holding」拒絕我的事件流）把它翻出來的。**
修法：把這筆股利歸給該檔**最後一次已結束的嘗試**，也就是真正賺到它的那次持有。
修好後每個帳本的股利現金與該檔全部 DIVIDEND 事件總額完全相等。

**二、「非命中」窗口會跨過命中接起來。** 見第 4 節的更正說明。

**兩個缺陷對結論的影響：零。** 逐格重算後，
**十五個帳本的「連續 20 次嘗試」數字一格都沒有變**，四張卡的重新評分結果也完全相同。
股利是正現金，漏算只會讓數字更難看，所以原本的更正方向如果有偏差，也是偏保守的那一邊。
`as_published` 那一欄刻意保留**原本會漏掉股利的配對**，因為那一欄的用途就是重現四張卡真正印出來的數字。

**方法上的一點：** 這兩個缺陷都不是靠再讀一次自己的程式找到的，
是**拿另一個獨立實作去撞它**才掉出來的。第 9 節說「擁有者用常識抓到我用程式沒抓到的錯」，
這裡是同一件事的另一個版本——**獨立的第二實作比自我複查有效。**
