# Full-history web read model

Stable asset: `opportunity-history-web.v1`. Its purpose is to browse retrospective market opportunities and inspect saved method evidence. It is not a strategy approval, a point-in-time signal dataset or a complete market-data backup.

## Entry points

- Website: `#market`; retained eight-case view: `#market-preview`; original fixed-window view: `#market-legacy`.
- Versioned read-only API: `/history-api/opportunity-history/v1/metadata`, `/frame?date=YYYY-MM-DD`, `/security/{code}?date=YYYY-MM-DD`.
- Shared producer CLI: `scripts/query_opportunity_history.py --manifest <saved catalog manifest> --code 2609 --date 2021-07-23`. It reports fraction units; HTTP display rows report percent.
- Trusted default input is `inputs/producer-preview/catalog-v2/manifest.json` in this task. HTTP never accepts input paths or alternative manifests.

For the current Vite development page, run the dedicated read-only API from this worktree:

```powershell
uv run --group viewer python -m uvicorn research_api.main:app --host 127.0.0.1 --port 8517
```

Then use the existing Vite page at port 5177. The separate port preserves the existing research API at 8503. A production build served by the updated `research_api.main` uses the same `/history-api` routes without a dev proxy.

## Scope, storage and restoration

The presentation manifest links producer identities separately from this consumer version. The copied read bundle contains producer `catalog-v2` and `runs/native` physically, without links. It is ignored local data, approximately one gigabyte, not committed large binaries. The original producer worktree remains canonical. Acquisition/normalization stays in `shioaji_stock_prices`; consumer projections belong in `research_core`, HTTP transport in `research_api`, and UI adapters in `research_web`.

Git alone can restore code and method-source bytes, but **cannot restore this full local catalog/native copy**. From the repository root run `uv run python -m scripts.restore_opportunity_history --source <existing-producer-task-directory>`. The executable entry verifies the pinned source through the complete reader gate before writing, physically copies `catalog-v2` and `runs/native` to this task's new `inputs/producer-preview`, and checks all copied bytes against their pre-validation hashes. It rejects links/junctions, overlap, existing destinations and changed bytes; failed partial copies remain for inspection. Restart the API after restoration. A missing catalog is explicitly unavailable in the UI, with a link to the separate bundled eight-case preview. Do not archive the only retained producer copy. This copy does not include the original price/action source snapshots and is not a complete research backup. The unresolved full backup policy remains a separate owner decision.

Known limits: 2010–2012 adjustment completeness; missing/downlisted identity coverage; 200 issuers of fine classification evidence still pending; unapproved wave/launch rules; no reliable historical market cap; full-market ETF/strategy holding comparison not connected. The existing research library and its account evidence remain available separately. Unknown holding information is not a missed opportunity verdict.

This asset can help future research compare membership and exact price-path dates. It does not add an unseen validation period or authorize research rule changes after viewing these histories.
