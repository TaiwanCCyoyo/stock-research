# Dashboard 改版（research_web）

Owner 於 2026-10-24（Asia/Taipei）提出並逐項選定。這是呈現層工作，不是新研究；
不改價格、研究判定、已存回測、報告位元組或任何釘選證據。

## 為什麼改

1. **入口重疊、看不懂差別。** 「策略」只是一份 2019–2023 的舊帳戶模擬快照（2 個），
   「研究報告」（4 份網頁報告）和「研究歷程」（全部研究目錄）又互相重複。新研究
   永遠不會出現在「策略」。
2. **樣子樸素。** 字小、對比低、層次平；每頁頂端都是技術說明條。
3. **文字寫給開發者看。** 版本代號、快照、資料世代、登錄狀態出現在一般頁面上。
4. **Owner 之後主要用手機看。**

## Owner 已定案的方向

| 項目     | 決定                                                                                                                             |
| -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 導覽     | 5 個：首頁 / 研究 / 飆股地圖 / 共用資料 / ETF 圖鑑。手機放在**底部分頁列**                                                       |
| 研究頁   | 「研究報告」+「研究歷程」合成「研究」；「策略」「比較」退出主選單，從研究卡片進入；舊帳戶模擬標「舊資料」                        |
| 排版     | ③ 單欄動態牆：由上往下讀；研究頁為依月份分組的時間軸。寬螢幕研究卡片可排兩欄                                                     |
| 物件風格 | 柔和卡片：大圓角、柔陰影、無框線；膠囊形按鈕與標籤；粗圓長條                                                                     |
| 顏色     | 使用者自選 8 種主題 × 日光／夜色：霧林綠、海霧藍、櫻花粉、星夜紫、暖沙金、檸檬汽水、夕陽橘、墨色極簡                             |
| 泡泡特效 | 每個主題各有飆股地圖裝飾特效（例：櫻花粉合併冒愛心、破裂散花瓣）。只裝飾，不改泡泡大小、位置或分組；可關閉；遵守「減少動態效果」 |
| 文案     | 讀者導向，見下方文案規則                                                                                                         |

樣稿（未提交，含私有研究數字）：主 checkout 的
`.tmp/dashboard-mockups/layouts.html`（選 ③ + 柔和卡片）與 `themes.html`（8 主題與特效）。

## 文案規則

| 拿掉（或收進「ⓘ 資料來源」展開）                       | 縮成一句白話，但**保留意思**                     |
| ------------------------------------------------------ | ------------------------------------------------ |
| 版本代號、SHA-256、研究代號（task ID）                 | 「歷史統計，不是買賣訊號」類的非投資建議提醒     |
| 「固定快照」「共用資料世代」「登錄需更新」「checkout」 | 合成示範模式的「示範資料，不是真實結果」         |
| 一大段來源與完整性說明                                 | 研究自身的限制（如「事後描述，不是可交易報酬」） |
|                                                        | 資料期間（例：資料期間 2010/01 – 2026/10）       |

`openspec/specs/research-output-safety` 要求保留風險與限制說明，所以右欄是縮短，不是刪除。
登錄有問題的卡片不對讀者顯示錯誤字樣；問題由資料端修正。

## 相容性限制

- **舊網址照常可用**：`#reports`、`#history` 導向 `#research`；`#report/<id>`、
  `#strategy/<id>`、`#compare`、`#market`、`#data/<code>` 不變。`docs/en/study-presentation.md`
  與兩份 `study-presentation` SKILL.md 若引用網址，同步更新。
- **主題 ID**：保留 `forest`、`ocean`、`plum`、`sand` 四個既有 ID，讓已存的
  `atlas.palette` 照常對應；新增 `sakura`、`soda`、`sunset`、`ink`。
- **網頁報告**：已發佈報告各自釘選一份 `report-kit` v1，只認得前述四個 palette。
  Studio 傳給報告時，新主題要對應到最接近的舊 palette（例：sakura→plum、soda→forest、
  sunset→sand、ink→forest）。**不改任何已發佈的報告位元組**；新 palette 支援留給未來的 report-kit 版本。
- 研究工具（`#research`、`#wave-lab`、`?legacy=1`）保留可達，但不放進主選單。
- `openspec/specs/research-dashboard*` 的既有功能（K 線工作台、交易明細、資料品質）不移除。

## 和資料整理工作的分界

另一個 session（「資料架構」）正把散在 5 種格式的研究紀錄整理成每個研究一份
`study.json`。分界：

- **本工作**：外殼、設計 token、主題、導覽、首頁、研究頁 UI。研究頁建立在一個
  正規化的卡片型別上，先從現有 history API 餵資料。
- **資料工作**：`study.json` 格式、補登、以及把研究頁的資料來源改接 `study.json`。
- `20261010-hhhl-v4-probability` 的「登錄需更新」由資料工作處理，不列在這裡。

## 驗收

- `research_web` 測試與 build 通過；既有 `tests/`、`scripts/tests/` 相關測試通過。
- 每個主要頁面在 375px 與 1440px、日光與夜色下截圖確認，沒有左右捲動。
- 8 主題切換後整站顏色一致；特效關閉與減少動態效果時不播放。
- 舊網址仍能打開對應內容；已發佈報告仍能載入且主題對應正確。
- 一般頁面看不到版本代號、SHA、task ID、快照、世代、登錄等字樣；安全與限制提醒仍在。
