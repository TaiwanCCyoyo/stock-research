## 1. 這張卡為什麼是這張卡

三個診斷把問題定位到「保留」這一步：

1. **篩選器沒有錯過。** 三年、每年當年漲幅最大的 12 檔，**36/36** 都進過分數的前 30 名，多數
   在主升段還沒走完時就進來（2344 在 **18.9** 進來，後面還有 **+341%**）。
2. **引擎買了。** 現行 `momentum_k10__hold20` 在驗證期持有 2344、2408、8210、7610、4909。
3. **然後賣掉，只吃到約六分之一。** 十檔最大的漲幅裡，從各自進場點算起平均只實現 **12%**。

而現行規則賣掉 2344 的原因，量出來是兩個：它在 252 個被排除的日子裡，中位數低於自己波段高點
15.8%（正常回檔），但其中 **68 天它就在自己的高點附近**——2025-05-26 創新高、20 日漲 50%，
排名 **170**。看起來這就是「該修的地方」。

## 2. 兩個新指標，以及為什麼要有第三個

**飆股母體用門檻定義，不是事後挑。** 一檔股票屬於某視窗的飆股母體，若在它**首次進入分數前十名**
之後的 250 個交易日內，總報酬還原收盤價曾經比首次進入那天高出 **+150%** 以上。訓練期 **64 檔**、
驗證期 **72 檔**（分別出自 593 與 455 檔曾進過前十名的名字）。門檻也用家族呈現（+100/150/200/300%）。

- **捕捉率**：母體中有幾成被這條臂持有過。
- **參與率**：持有過的那些，實現報酬 ÷ 從**首次浮現**到視窗結束期間的最高可得報酬。分母錨在
  「首次浮現」而不是谷底、也不是各臂自己的進場點——錨在谷底會塞進一段誰都抓不到的漲幅、把每條臂
  同等拉低；錨在自己的進場點則會讓晚進場的臂因為分母變小而顯得漂亮。首次浮現對每條臂都一樣，
  因為進場規則是共用的。

**跑完之後補的第三個指標，因為前兩個會互相抵消。** `pool`：**這個視窗所有飆股報酬中，這條臂拿到
幾成**（分子是母體名字上的實現報酬總和，分母是可得報酬總和；沒買到的名字分子為 0、分母照算）。
用報酬加總而不是比率平均，是因為「不能一年完全錯過所有大飆股」講的是大的那幾根，比率平均會讓一
堆小的把它們投票投掉。

## 4. 失敗的方式，就是答案

### 4.1 保留與覆蓋是直接的零和，因為只有十個槽

`give30` 與 `give40` **通過了規則 1**——參與率從基準的 11% 拉到 **29%** 與 **32%**，接近三倍，
正是這張卡想要的效果。它們死在規則 2：**捕捉率從 94% 掉到 47% 與 33%**。

而 `pool` 顯示這個交換幾乎是等價的：

| 訓練期   | 捕捉率 | 參與率 |  pool |
| -------- | -----: | -----: | ----: |
| `rank30` |    94% |    11% | 12.3% |
| `give30` |    47% |    29% | 11.3% |
| `give40` |    33% |    32% |  8.3% |

**抱得久，就買得少。** 帳戶只有十個槽，一個槽被一檔飆股佔住三個月，那三個月裡出現的每一檔新飆股
都進不來。`slots` 欄把這件事量出來：訓練期每條臂平均用掉 **9.2 到 9.9 個槽**、73～89% 的交易日
滿倉。在一個滿的十格書架上，多留一本就是少放一本。

### 4.2 而在驗證期，真正卡住進場的不是槽位，是現金——而且是全面性的

驗證期的 `slots` 只有 6.7～8.6、滿倉比例只有 13～36%——書架沒滿，卻還是買不夠。

**引擎的 `cash_blocked_entry_count` 看起來像答案，但它不能直接讀。** 它每根 K、每個「試買但買不起」
的候選各記一次，而本策略的買進迴圈只在**成功**時才扣掉剩餘槽位——所以現金不足的那一根 K，會把
前十名沒持有的名字全部試一遍、記十次。基準線在驗證期記到 2,878 次（成交 243 次），那個比例是
真的，但它不是「錯過了 2,878 檔」。

**所以直接把現金路徑重建出來。** 每筆成交紀錄都有 `total`，累加即得每日現金；重建值與引擎自己
回報的期末現金**逐格相符（差 0.00）**，所以這條路徑可以拿來下結論：

| 臂 / 視窗       | 有空槽的交易日 | 其中現金 < 一個槽（100 萬） | 期間現金中位數 |
| --------------- | -------------: | --------------------------: | -------------: |
| `rank30` 訓練期 |     146（12%） |                   39（27%） |     **14.34M** |
| `rank30` 驗證期 | **483（76%）** |             **483（100%）** |      **0.51M** |
| `atr3` 驗證期   |     358（56%） |                 358（100%） |          0.77M |
| `give40` 驗證期 |     514（81%） |                 514（100%） |          0.45M |
| `low60` 驗證期  |     571（90%） |                 571（100%） |          0.31M |

**兩個視窗的瓶頸是相反的，而且驗證期那一列是絕對的，不是邊際的。**

- **訓練期綁在槽位上**：88% 的交易日書架是滿的，而現金中位數 **14.34M**——比初始資金還多，因為
  帳戶漲到 30M 而槽位還是固定 100 萬。閒置的是資金，稀缺的是槽。
- **驗證期綁在現金上**：76% 的交易日有空槽，而**那些日子裡 100% 湊不出一個槽的錢**，現金中位數
  只有 **0.51M**。

原因是尺寸錨在**初始**資金：十個槽 × 100 萬 = 1,000 萬，而驗證期最大回檔 −53%，帳戶淨值有很長
一段時間**低於 1,000 萬**。也就是說，這個配置想部署的書架，在它自己最需要進場的那段期間裡是
**物理上湊不出來的**。驗證期的低捕捉率有很大一部分根本不是出場規則造成的。

**這正是卡 B 的題目，而且現在的數字是「有空槽的日子裡 100% 買不起」，不是一個模糊的比例。**

## 5. 這對整條線的意義

把六個研究放在一起：

| 研究                            | 換掉的東西         | 結果                           |
| ------------------------------- | ------------------ | ------------------------------ |
| `20260823-regime-overlay`       | 加空頭偵測         | 29 臂 0 通過                   |
| `20260824-ranking-horizon`      | 排序視窗           | 8 臂 0 通過                    |
| `20260824-value-chain-ignition` | 族群分組           | 訓練期顯著為負                 |
| `20260826-tail-selection`       | 衡量的尺規（右尾） | 篩子有效，10 個次要排序 0 通過 |
| **本研究**                      | **出場規則**       | **13 臂 0 通過，對照組最好**   |

**選股、排序、分組、出場，四個都不是瓶頸。** 剩下沒被動過的只有一個：**書架本身的形狀**——十個
等權槽位、每槽固定初始資金的 1/10。§4.1 與 §4.2 分別指出它的兩個綁定方式（槽位數、以及回檔後
湊不出槽），而 §0 的天花板（訓練期最好 13.8%、驗證期 6.8%）就是它造成的。

**所以下一張卡（卡 B）是有根據的，不是換下一個旋鈕。** 它要動的是槽位數與部位大小，而你已經指定
了目標：行情存在時至少約 50% 資金參與。這裡再加上兩個本研究量出來的約束：

- 槽位變多會提高捕捉率（`rank120` 訓練期捕捉率 97%），但每檔的權重變小；
- 槽位尺寸若繼續錨在**初始**資金，帳戶淨值低於初始資金時整個書架就湊不出來（§4.2：驗證期有空槽
  的 483 個交易日，100% 買不起），而帳戶淨值遠高於初始資金時又會閒置大量現金（訓練期現金中位數
  14.34M）。**同一個常數在兩個視窗各錯一次，方向相反。** 改成錨在當期淨值是卡 B 的第一個家族。

## 6. 限制

**這是一次乾淨的否定，但它否定的是「換出場規則」，不是「保留沒有價值」。** `give30` 把參與率拉到
接近三倍是真的；它在十個槽的限制下換不到總量，不代表在別的書架形狀下也換不到。卡 B 會同時動槽位
與尺寸，那時 `give30` 值得再測一次。

**驗證期是這條線第六次讀它。** 訓練期是主讀數；驗證期的排序（`rank30` 第一）與訓練期（`rank120`
第一）不同，這本身就是一個提醒：這兩個視窗對「放寬到什麼程度」的意見從來沒有一致過，
`20260823-turnover-mechanism` 早就記錄過同一件事（訓練期單調有利、驗證期反轉）。

**結構出場沒有最低持有期，基準有。** `min_hold_bars = 20` 只擋排名驅動的賣出，結構停損想觸發就
觸發。這是預先登記時就寫明的不對稱，規則 3（周轉）是它的價格——而 `atr2` 正是唯一被規則 3 擋下的
臂（訓練期 12.92、驗證期 13.35，超過 12 的上限）。

**`pool` 是跑完之後才加的指標。** 它不參與任何一條驗收規則的判定（那些規則的結果在 §3 之前就已經
決定），只用來解釋為什麼規則 1 與規則 2 會互相抵消。這一點寫在這裡而不是留給讀者推斷。
