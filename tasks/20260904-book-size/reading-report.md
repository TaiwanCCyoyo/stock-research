# 增加持股數的歷史取捨：先看修正後結果

閱讀版更新：2026-11-02。以下整理保存的研究與後續更正，未重跑市場計算。

## 原本的問題

增加持股容量後，訓練期的報酬取捨會在另一段期間反轉嗎？

## 目前能回答的事

修正停牌持股漏佔名額後，這次驗證期的30檔版本仍比10檔版本有較高報酬與飆股份額；這沒有證明30檔最佳，也不符合目前最多五檔的操作範圍。

## 實際比較

原契約固定動能分數、20日最低持有與排名出場，只動容量。訓練比較10／20／30檔；驗證新增30檔，10檔沿用既有結果。期間分為2019–2023與2024-01-01至2026-08-14；驗證期事後漲150%的比較母體有72檔。

原V5沒有把當日無報價的持股算入容量。原報告的30檔驗證報酬127.3%屬於這個有缺陷版本；後續slot-accounting保存了V8修正結果：

| 修正後驗證期           |   10檔 |   30檔 |
| ---------------------- | -----: | -----: |
| 帳戶報酬               |  81.5% | 120.4% |
| 最大回落               | −53.3% | −41.9% |
| 飆股捕捉率             |  0.722 |  1.000 |
| 飆股份額（pool share） | 0.0682 | 0.1895 |
| 實際持股峰值           |     10 |     30 |

捕捉率是是否碰到母體內股票；pool share衡量取得的漲幅份額，兩者都不等於帳戶報酬。原先的超額持有與平均佔槽數不可繼續當正常30檔配置引用。

## 尚未回答與決策意義

原預先指定的「pool share和報酬都上升」仍成立，保留歷史判定。但只比較有限容量、單一驗證視窗，沒有測到最佳檔數，更不能從這張表要求owner持有30檔。

後續execution-reality記錄owner定案最多五檔，30檔轉為歷史參考；executable-fills再指出同收盤成交結果不能直接視為可取得報酬。新討論應在五檔約束內找方法，不把這張舊容量曲線當產品需求。

## 閱讀界線

這是1000萬元、同日收盤成交的舊模型；只能在同一資料、母體與版本內比較，不能用它取代200萬元五檔可執行帳戶。

原始研究判定仍保留；這份閱讀版可供理解與討論，不代表策略獲准或新增獨立驗證。
