# 修正容量計算後，30 檔在這段驗證期仍比 10 檔報酬高

閱讀版更新：2026-11-04。數字沿用下列保存來源。

**研究問題：** 增加同時持股檔數，會如何改變帳戶報酬與取得的大漲股票漲幅？

2024-01-01 至 2026-08-14，修正停牌持股漏佔名額後，30 檔模型的帳戶報酬為 120.4%，10 檔為 81.5%；30 檔也取得較多大漲股票的漲幅。這次只比較有限檔數，沒有找到最佳持股數。

這裡的漲幅份額，是固定期間內事後大漲股票中，策略取得的漲幅總和除以這批股票可得漲幅總和；沒買到的也留在分母，並非帳戶報酬。

**主要限制：** 這是1000萬元、同日收盤成交的舊模型；只能在同一資料、母體與版本內比較，不能用它取代200萬元五檔可執行帳戶。

本篇比較持股容量；[停牌持股計算更正](../20260904-slot-accounting/report.md)提供下表採用的修正數字。[後續操作需求](../20260906-execution-reality/report.md)則把研究目標固定為最多五檔，屬需求更新。

## 實際比較

「10 檔／30 檔」是同時持股上限，每次預算為 1,000 萬元除以該上限。排名由最近 20 與 60 個交易日漲幅合成；最低持有 20 日表示排名變差時也先等滿這段時間。

「大波段份額」（原表 pool share／pool_capture）把母體股票實際取得的漲幅加總，再除以同一母體可得漲幅的總和；沒買到的股票也留在分母。例如份額 0.20 代表取得這批股票可得漲幅總和的兩成，不是帳戶賺了 20%。

原契約固定動能分數、20日最低持有與排名出場，只動容量。訓練比較10／20／30檔；驗證新增30檔，10檔沿用既有結果。期間分為2019–2023與2024-01-01至2026-08-14；驗證期事後漲150%的比較母體有72檔。

原V5沒有把當日無報價的持股算入容量。原報告的30檔驗證報酬127.3%屬於這個有缺陷版本；後續slot-accounting保存了V8修正結果：

| 修正後驗證期           |   10檔 |   30檔 |
| ---------------------- | -----: | -----: |
| 帳戶報酬               |  81.5% | 120.4% |
| 最大回落               | −53.3% | −41.9% |
| 飆股捕捉率             |  0.722 |  1.000 |
| 飆股份額（pool share） | 0.0682 | 0.1895 |
| 實際持股峰值           |     10 |     30 |

捕捉率的分母是驗證期 72 檔事後大漲股，分子是模型至少持有過一天的檔數；1.000 表示 72 檔都曾持有，0.722 表示約 72.2%。最大回落以帳戶先前高點為分母，並非相對起始本金。原先的超額持有與平均佔槽數不可繼續當正常30檔配置引用。

## 這次還沒有回答什麼

原預先指定的「pool share和報酬都上升」仍成立，保留歷史判定。但只比較有限容量、單一驗證視窗，沒有測到最佳檔數；後續需求改為最多五檔。

後續execution-reality記錄研究委託人定案最多五檔，30檔轉為歷史參考；executable-fills再指出同收盤成交結果不能直接視為可取得報酬。因此本篇三十檔結果只回答舊容量比較，未回答後來的五檔需求。
