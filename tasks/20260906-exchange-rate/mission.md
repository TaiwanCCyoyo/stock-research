# 任務卡：兌換率是書架的性質，還是規則的性質？——並且更正我自己上一張卡的比較

`20260906-exchange-rate`，2026-09-06。**這是一張量測卡，不提名任何候選。**
本文件在讀到任何新數字之前寫完。

## 1. 要更正的東西，先寫在最前面

`20260905-min-hold` 報告第 5.3 節我寫了一個猜想：

> 兩個機制完全不同的賣出規則——一個看價格、一個看時間——在樣本外掉在同一條曲線上……
> 那個兌換率不是某個規則家族的性質，是這個書架本身的性質。

**那個比較是錯的。** 我拿 `give20` 的**訓練期**數字（週轉 2.62、pool 0.1256）去比 `hold80` 的
**驗證期**數字（週轉 2.72、pool 0.1247）。而同一張卡的第 5.1 節剛剛證明**週轉率會隨市況大幅移動**
（`hold40` 訓練 2.90 → 驗證 5.08），所以跨視窗配對兩個「週轉率相近」的點**沒有意義**。

**在同一個視窗（訓練期）內重新比，兩個家族並不重合：**

| 帳戶週轉區間 | 時間型（min_hold）              | 價格型（give-back）             |      差距 |
| ------------ | ------------------------------- | ------------------------------- | --------: |
| 2.4 ~ 3.0    | `hold40` 2.90 / pool **0.3147** | `give20` 2.62 / pool **0.1256** | **2.51×** |
| 1.8 ~ 2.3    | `hold60` 2.16 / pool 0.2258     | `give25` 1.94 / pool 0.1759     |     1.28× |
| 1.1 ~ 1.6    | `hold80` 1.56 / pool 0.2459     | `give30` 1.24 / pool 0.2173     |     1.13× |

**所以在訓練期，時間型明顯比價格型便宜，而且差距隨週轉率上升而擴大。**

**但這個結論靠不住，原因很具體**：最大的那個差距（2.51×）幾乎完全來自 `hold40` 的 0.3147，
**而那正是驗證期已經否決掉的那個數字**（驗證期掉到 0.1366，低於基準）。把 `hold40` 拿掉之後，
剩下兩個區間的差距是 1.28× 與 1.13×——**可能有差，也可能只是雜訊。**

而機制上的差異是說得通的、不是硬湊的：兩個家族的 capture 幾乎一樣（`hold40` 0.984 / `give20`
0.969），差的是 **participation（0.281 vs 0.139）**。**回吐停利會在飆股的正常回檔中把它停掉**，
時間下限不會。`20260903-entry-window` 與 `20260826-runner-retention` 都從別的角度量到同一件事。

## 2. 這張卡要問的唯一問題

**在同一個視窗、相同的帳戶週轉率下，價格型與時間型的出場規則會不會給出相同的 pool share？**

- **會** → 兌換率是書架的性質。「少交易」與「抓飆股」在 K=30 上是結構性衝突，
  **那是一個要交給擁有者決定的取捨，不是還能再測的研究問題**，我停止尋找更便宜的出場規則。
- **不會** → 存在比較便宜的機制，而「哪一種賣法」重新變成一個值得測的軸。

## 3. 做法與開封帳，講清楚

**驗證期已經有的**：`hold20`（基準）、`hold40`、`hold60`、`hold80` 四格。

**這張卡要新開三格驗證期**：`give20`、`give25`、`give30`。

依訓練期→驗證期的週轉率放大倍率（約 1.6~1.75×）估算，這三格的驗證期週轉率會落在
大約 4.5 / 3.3 / 2.1，**正好和 `hold40`（5.08）、`hold60`（3.50）、`hold80`（2.72）
形成三組可配對的比較**，而不是只有一組。

**必須明講的一件事：這不是在救 give-back。** `20260905-wide-giveback` 判它負面
（五格只有一格過、無平台、那一格是兩檔股票撐的），**那個判決不變，而且不論這張卡的驗證期
數字多好看都不變**——那張卡是拿它當候選，這張卡是拿它當**量尺**。
一個量尺在驗證期表現好，不會讓一個已經被平台關卡否決的候選復活。

## 4. 主要指標與配對規則

指標定義與 `20260905-wide-giveback`、`20260905-min-hold` 完全相同（帳戶層級週轉、成本磨損、
pool share、capture、participation），三張卡的數字可以直接並排。

**配對規則**：兩個家族的格子，若驗證期帳戶週轉率相差在 **±20% 以內**，算一組可比較的配對。
每一組比較 pool share 的比值。

## 5. 預先宣告的三種結論

| 結果                                                  | 結論                   | 下一步                                               |
| ----------------------------------------------------- | ---------------------- | ---------------------------------------------------- |
| 每一組配對的 pool share 比值都在 **0.80 ~ 1.25** 之間 | **兌換率是書架的性質** | 停止找更便宜的出場規則，把取捨整理成選擇題交給擁有者 |
| 有任一組配對的比值 **≥ 1.25 或 ≤ 0.80**，且方向一致   | **機制有差**           | 較便宜的那一邊是新的軸，值得單獨設計                 |
| 配對的方向不一致（一組時間型贏、另一組價格型贏）      | **無結論**             | 樣本不足以分辨，不再花驗證期額外開封                 |

**額外預先宣告一條，防止我自己事後挑數字**：訓練期那個 2.51× 的差距**不列入本卡的判定**，
因為它建立在一個已經被驗證期否決的格子上。判定只看驗證期的三組配對。

## 6. 我對結果的事前預期，寫成方向

**我預期第一種結論（兌換率是書架的性質）。** 理由：`20260905-min-hold` 的驗證期顯示，
時間型在樣本外的 capture 崩得比訓練期快得多（0.984 → 0.806 → 0.722），
**而訓練期讓時間型看起來便宜的那個優勢，正是靠 capture 撐著的。** capture 一崩，優勢就沒了。

**如果結果是第二種（機制有差）而且是價格型比較便宜，那我這條線對這件事的理解是反的**，
必須在報告裡當成主要發現寫，而不是當成註腳。

## 7. 先天限制

**單一驗證視窗、三組配對。** 這不足以支持「曲線」這種說法，只夠支持「在這三個週轉率附近，
兩個機制給的 pool share 是否同一個量級」。**本卡不宣稱顯著性，也不外推到未測過的週轉率。**

**飆股母體在兩個視窗不同**（訓練 64 檔、驗證 72 檔），所以驗證期的 pool share 只能和
驗證期的比。
