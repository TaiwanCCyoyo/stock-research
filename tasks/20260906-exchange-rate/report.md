# 兌換率：機制確實有差，但差得比訓練期小一個量級。而取捨本身是真的

任務 `20260906-exchange-rate`，2026-09-06。**量測卡，新開三格驗證期，不提名任何候選。**

## 0. 四句話

**第一，我先更正自己。** `20260905-min-hold` 第 5.3 節我把訓練期的 `give20` 和驗證期的 `hold80`
配成一對，宣稱兩個機制掉在同一條曲線上。**那個比較沒有意義**——同一張卡的第 5.1 節剛證明
週轉率會隨市況大幅移動（`hold40` 訓練 2.90 → 驗證 5.08）。這張卡在**同一個視窗**內重做。

**第二，預先宣告的判定觸發了「機制有差」，方向是時間型比較便宜——但幅度很小。**
三組配對的 pool share 比值是 **1.24 / 1.30 / 1.09**，門檻是 1.25。只有一組越線，而且只越了 0.05。

**第三，訓練期把這個差距誇大了一個量級。** 訓練期最上面那一組是 **2.51×**，驗證期同一段是
**1.24×**。那個 2.51 幾乎全部來自 `hold40` 的 0.3147，**而驗證期已經否決掉那個數字**。
我在 `mission.md` 第 5 節就預先宣告訓練期那個差距不列入判定，這裡照辦。

**第四，也是要交給擁有者的那一句：兩個機制都很貴，而且貴得差不多。**
把帳戶年化週轉壓到 3.0 以內，驗證期的 pool share 從基準的 **0.1895** 掉到
**0.1247（時間型）或 0.1142（價格型）**——**付掉 34% 或 40%**。
**沒有任何一個設定同時滿足擁有者的週轉限制與 80% 的飆股份額。**

## 2. 三組配對

配對規則寫在事前：驗證期帳戶週轉率相差 ±20% 以內算一組。實際配出來的三組**幾乎完全對齊**：

| 時間型 | 週轉 |   pool | 價格型 | 週轉 |   pool |     比值 | 判定         |
| ------ | ---: | -----: | ------ | ---: | -----: | -------: | ------------ |
| hold40 | 5.08 | 0.1366 | give20 | 5.02 | 0.1100 | **1.24** | 同一量級     |
| hold60 | 3.50 | 0.1372 | give25 | 3.59 | 0.1055 | **1.30** | 時間型較便宜 |
| hold80 | 2.72 | 0.1247 | give30 | 2.72 | 0.1142 | **1.09** | 同一量級     |

依 `mission.md` 第 5 節：有一組 ≥ 1.25 且三組方向一致（都 > 1.0）→ **「機制有差，時間型較便宜」**。

**但這個判定必須配著幅度讀。** 三個比值是 1.24 / 1.30 / 1.09，平均 1.21。
**時間型在樣本外比價格型多留住大約兩成的飆股份額**，而不是訓練期看起來的兩倍半。
門檻 1.25 只被跨過 0.05，**如果我當初把門檻寫成 1.35，這張卡就會判「同一條曲線」。**
我不改門檻，但這個脆弱性必須寫在這裡。

## 3. 差在哪裡：驗證期是 capture，不是 participation

訓練期我看到的差異是 participation（`hold40` 0.281 對 `give20` 0.139），
**驗證期不是這樣**：

| 配對            | capture（時間型 / 價格型） | participation（時間型 / 價格型） |
| --------------- | -------------------------- | -------------------------------- |
| hold40 / give20 | **0.972 / 0.847**          | 0.141 / 0.123                    |
| hold60 / give25 | **0.806 / 0.667**          | 0.151 / 0.114                    |
| hold80 / give30 | **0.722 / 0.583**          | 0.179 / 0.126                    |

**在相同的週轉率下，時間型每一組都多碰到約 14 個百分點的飆股母體。**
機制上說得通：回吐停利會在飆股的正常回檔中把部位停掉，**而停掉之後那個名字就從母體裡永久消失了**；
時間下限不會主動停損，它只是延後排名驅動的賣出。

## 4. 一件配對數字沒說、但帳戶數字說得很大聲的事

**價格型在帳戶層級輸得比 pool share 顯示的更難看。**

|                 |                報酬 |          回落 |
| --------------- | ------------------: | ------------: |
| hold60 / give25 | **66.0** / **31.7** | −41.9 / −45.5 |
| hold80 / give30 | **70.8** / **33.8** | −42.1 / −47.9 |

**報酬差了一倍以上，回落還深 4~6pp。** pool share 只差一成到三成，帳戶報酬卻差一倍——
這兩個問的不是同一件事，**而擁有者實際上兩個都要**。

## 6. 這張卡不能推論的事

**三組配對，單一驗證視窗。** 判定跨過門檻的幅度只有 0.05，**這不是一個穩健的判定**，
換一個視窗很可能翻面。第 2 節已經寫明如果門檻訂在 1.35 結論就會相反。

**只測了兩種機制。** 排名型出場（`exit_rank` 家族）沒有在 K=30 的 V8 上測過，
所以「所有機制都一樣貴」這句話沒有被檢定，只有「這兩種都很貴」被檢定。

**pool share 的分子是 72 檔的和**，未做集中度檢查——本卡不提名任何東西，
但如果第 5 節的表要被拿去做決定，`hold80` 那一格應該先跑一次集中度。
