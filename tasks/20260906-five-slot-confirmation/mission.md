# 任務卡：五檔候選者的穩健性確認——沒有新視窗可用，所以確認的是機制不是運氣

`20260906-five-slot-confirmation`，2026-09-06。**本文件在跑任何一格之前寫完。**

## 0. 先承認這張卡做不到什麼

**這不是一次封存驗證期的確認，而且不可能是。**

`20260906-five-slot-baseline` 的那一格（`all` / top_k=5 / exit_rank=30 / min_hold=0）
**訓練期與驗證期都已經被讀過**。而資料只到 **2026-08-21**，驗證期結束在 2026-08-14，
**中間只剩 5 個交易日，不構成任何窗口。** 特徵表 `features_v2.parquet` 的可用起點是
2019-06-19，之前也沒有東西。

**所以「再開一個沒看過的視窗」這條路不存在，我不會假裝它存在。**

**這張卡能做的、而且是真的沒被看過的，是四組「量」：**

1. **鄰域**——`top_k` 與 `exit_rank` 在候選者周圍的格子，除了 k5/er30 以外**一格都沒跑過**。
2. **拿掉分數的任一項**——`all` 有八個特徵，**八個 leave-one-out 版本一個都沒跑過**。
3. **逐年拆解**——候選者的報酬從來沒有按年分解過。
4. **codex 合約的 gate 2 / 3 / 4**——從來沒有套用在這個候選者上。

**一個結果如果是真的機制，這四組會一起支持它；如果是運氣，它會在其中至少一組上散掉。**
這比「再看一次同一個數字」有價值，但它**不能取代封存驗證期**，報告必須這樣寫。

## 1. 候選者與對照組

**候選者**：`all` / `top_k=5` / `exit_rank=30` / `min_hold_bars=0`，V8，NT$2,000,000。
**對照組（現行做法）**：`momentum` / `top_k=30` / `exit_rank=30` / `min_hold_bars=20`，同引擎同資金。

對照組的驗證期已知為 **+118.9% / −41.9%**；**訓練期在 200 萬上還沒跑過，本卡補跑一格**，
因為所有比較都必須同資金同引擎。

**「贏過對照組」的定義（寫死）**：報酬 ≥ 對照組，**且**最大回落不比對照組差超過 5.0 個百分點。

## 2. 四組門檻，全部預先宣告

### Gate A — 鄰域必須是一片，不是一個點

`top_k ∈ {3, 4, 5, 7, 10}` × `exit_rank ∈ {15, 30, 45}`，訓練期，`min_hold=0`，`all` 分數。

**通過條件：在 `exit_rank=30` 這一列，至少有 3 個連續的 `top_k` 值贏過對照組。**

理由：`20260905-wide-giveback` 五格只有一格過（而那一格 22% 的分子來自單一檔），
`20260905-min-hold` 有三格連續過**而驗證期全滅**——**所以平台是必要條件、不是充分條件**，
這裡把它當必要條件用。**如果只有 top_k=5 贏，那是一個點，不是一個機制。**

### Gate B — 分數不能依賴任何單一特徵

八個 leave-one-out 版本（每次拿掉 `all` 的一項），訓練期，k5/er30/hold0。

**通過條件：八個版本裡至多 1 個掉到對照組以下。**

理由：如果拿掉任一項就崩掉，那八項不是一個複合訊號，是一個剛好湊出來的組合。

### Gate C — 不能是某一年撐起來的

候選者在訓練期（2019–2023）與驗證期（2024–2026）的**逐年**報酬。

**通過條件：訓練期 5 年中至少 4 年為正，驗證期 3 年中至少 2 年為正。**

### Gate D — 借用 codex 合約的三條，逐條標明是哪一條

- **她的 gate 2**：連續 20 次虧損來回的**複利**跌幅 ≤ 20%。從成交明細算，**兩個窗都算**。
- **她的 gate 3**：漏掉 10% 的交易日，報酬仍為正且保留基準的 ≥ 70%。
  用 `20260906-execution-reality/candidates/rotation_ranker_v9.py`，**5 個 seed**，訓練期。
  **必須註明這比她的定義寬鬆**：她要的是「確定性排程、跳過 10% 的可執行訊號」，
  我做的是「隨機漏掉整個交易日」。**不得宣稱通過她的 gate 3，只能說同方向。**
- **她的 gate 4**：每筆委託延後一天，報酬仍為正且保留 ≥ 70%。
  用 `20260904-execution-delay` 的 lag 手法（把排名表整體位移，`on_bar` 原封不動）。
