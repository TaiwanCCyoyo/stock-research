# 排序視窗：機制成立，結論相反

## 0. 結論

**假設的機制是對的，推論是錯的。** 拉長視窗與風險調整**確實**把持股推向更大、更老、更穩的
名字——`skip_250_20` 的進場名單中位成交金額是基準線的 **2.67 倍**（每日 10.45 億對 3.92 億）。
但**沒有任何一條臂通過驗收**：8 條臂裡 0 條達到樣本外 1.5 倍的門檻，0 條形成高原。

而且量到了一個把整條路線關掉的數字：

**台積電在每一個分數下的樣本外每日名次中位數是 83 到 137 名（池子約 450 檔）。**
九個分數裡，最好的一天是第 10 名，而且只有一天。沒有任何一個分數曾經把它放進前十超過一次。

台積電在 holdout 漲了 **+319.9%**，贏過 93.4% 的市場。它的名次卻在一百名上下——因為
**名次是每日橫斷面的**，而 2.6 年 +320%（約每年 66%）在任何一個交易日都比不過那一百檔正在
噴出的名字。

所以：**0050 的 +236.7% 是「加權」的結果，不是「選股」的結果。** 指數贏過幾乎所有個股，不是
因為它的成分股是最強的，而是因為它**用市值加權**，而台積電佔了它的大部分權重。

**這關掉了一整個方向。** 任何用「報酬百分位」排序、等權重持有十檔的規則，結構上都不可能持有
台積電：**前十名等於當日合格池（約 450 檔）的前 2%，而台積電的每日名次落在前 20%–30%。**
要拿到指數那段報酬，唯一的方法是按市值加權，也就是持有指數本身。

## 2. 機制的確運作了，而且沒有用

`mission.md` 規則 5 事先就把「有沒有效」和「是不是照預期的機制有效」分開，因為這是**第四次**
讀同一個 holdout：報酬數字有四次機會看起來好，但「它到底買了什麼」只有一種方式是真的。

**機制成立。** 視窗越長、越風險調整，進場名單的成交金額中位數就越高：基準線每日 3.92 億，
`hz_250` 6.89 億（1.76×），`ra_250` 9.63 億（2.46×），`skip_250_20` 10.45 億（**2.67×**）。
中位 K 棒數也一致上升（1,437 → 1,509）。分數確實被推向更大、更老的名字。

**而且沒有帶來任何好處。** 最好的一條臂 `skip_250_20` 樣本外 +82.4%，基準線 +81.8%——在統計上
就是同一個數字。其他七條都更差。

這正是把兩個判斷分開的價值：如果只看報酬，結論會是「拉長視窗沒用」；把兩者一起看，結論是
**「拉長視窗做到了它該做的事，而那件事本身沒有用」**——這才是可以據以停止的資訊。

### 一個沒通過但值得記下的效率結果

`skip_250_20` 用 **2.59 次/格/年**的週轉拿到和基準線一樣的樣本外報酬，基準線是 8.89——**同樣的
報酬，29% 的交易量**，實際摩擦成本從約 4.4%/年降到約 1.3%/年。它通過規則 1（保住 70% 的訓練期
報酬）與規則 3，只倒在規則 2（要求 1.5 倍）。

它是**單格、依設計無法形成高原**，所以不構成一個發現；但「同報酬、三分之一成本、大一倍多的
持股」是一條值得在別的研究裡再驗一次的線索，不該和其他七條一起丟掉。

## 3. 為什麼排序永遠碰不到台積電

這是本研究最重要的量測。對每一個分數，逐日計算 2330 在合格池裡的名次：

| 分數               | train 中位名次 | train 最佳 | train 進前十天數 | holdout 中位名次 | holdout 最佳 | holdout 進前十天數 |
| ------------------ | -------------: | ---------: | ---------------: | ---------------: | -----------: | -----------------: |
| `hz_20_60`（基準） |            169 |         20 |                0 |              131 |           40 |                  0 |
| `hz_60_120`        |            205 |         30 |                0 |              137 |           50 |                  0 |
| `hz_120_250`       |            228 |         36 |                0 |              136 |           44 |                  0 |
| `hz_250`           |            233 |         50 |                0 |              134 |           45 |                  0 |
| `ra_60`            |            174 |      **4** |           **28** |              104 |       **10** |              **1** |
| `ra_120`           |            203 |          8 |                5 |              110 |           22 |                  0 |
| `ra_250`           |            206 |         29 |                0 |           **83** |           26 |                  0 |
| `skip_250_20`      |            231 |         57 |                0 |              137 |           46 |                  0 |
| 池子中位大小       |            388 |            |                  |              456 |              |                    |

**在 holdout，2330 的中位名次是 83 到 137 名，池子約 450 檔。** 九個分數合計，它進過前十的天數
總共是 **1 天**。

而 2330 在那段期間漲了 **+319.9%**，贏過 93.4% 的個股。

兩件事同時為真，因為它們量的是**不同的母體和不同的量測**，這點值得說清楚，因為很容易混淆：

- 「贏過 93.4% 的個股」是拿**整段區間**的報酬，在 1,860 檔有完整區間的名單裡比。
- 「中位名次 83–137」是拿**當日的移動報酬百分位**，在當天約 450 檔的**合格池**裡比。

前十名相當於合格池的**前 2%**；台積電的每日名次落在**前 20%–30%**。2.6 年 +320% 大約是每年
66%——在任何一個交易日，總有一百檔的近期報酬比它更陡。整段報酬很好，任何一天的近期斜率都不夠陡，
而排序只看得到後者。

**所以 0050 的 +236.7% 不是選股選得好，是加權加得好。** 指數贏過 93.4% 的成分股，是因為它把
權重壓在少數幾檔上，而那幾檔剛好是這段期間的贏家。一個等權重、按報酬百分位選十檔的規則，
無論視窗多長、是否風險調整，**在數學上都碰不到那個結果**。

值得記的一個細節：拉長視窗讓 2330 的名次**更差**（holdout 131 → 134~137），只有風險調整讓它
變好（`ra_250` 中位 83）。方向對，幅度差了兩個數量級。

## 4. 過程中修掉的三個缺陷

**4.1 缺值被當成中位數名次，會讓檢查碼決定整個投資組合。** 排序器沿用 `fillna(0.5)`。這對
「少數幾檔缺值」合理，但 **2019-12-25 之前快取裡沒有任何一檔有 250 根 K 棒**——所有長視窗臂
會把每一檔都算成 0.5、全體同分，然後由 CRC 尾數（刻意設計成任意但固定）挑出整個投資組合。
那條臂會用一整年持有十檔由檢查碼選出的股票，輸出看起來完全正常。已改成「該臂用到的每個特徵
都要有值才進排序」。**這在跑任何格子之前就抓到了**，並用註明日期的方式補進 `mission.md`。

**4.2 樣本外的驗收報酬全是 NaN。** 視窗起點 2024-01-01 早於第一根 K 棒 2024-01-02，as-of 查詢
回傳 −1，整欄變成 NaN。修法不是無條件夾到 0，而是分辨兩種情況：起點在第一根之前（視窗自己的
開始，用第一根是對的）與起點超出資料範圍（回傳 None）。第一版會把兩者一起夾掉。

**4.3 成交金額的單位錯了兩個數量級。** `liquidity` 是 Close × Volume 的移動中位數，而 Volume
以「張」（1,000 股）計，所以原始值的單位是**千元**。除以 1e6 印出來全是「0M」「1M」；正確是
除以 1e3，得到每日成交金額的百萬元。倍數欄（`liqX`）是無因次的，一直是對的——這也是為什麼
錯誤沒有改變任何結論，只是讓表看不懂。

## 5. 下一步

**不要再修排序。** 第 3 節是機制上的封閉結果：報酬百分位排序碰不到台積電，因為台積電不在報酬
的前 0.5%。拉長視窗、風險調整、跳過近月，三條路都試過，都把持股推向更大更穩的名字（最多
2.67 倍成交金額），都沒有改善報酬，也都沒有把 2330 排進前十。

真正剩下的是兩個彼此獨立的問題：

1. **加權方式，而不是選股規則。** 如果指數的優勢來自加權，那可測的是「在同一個選股規則下改變
   加權」——市值加權、或按流動性加權的十檔組合。這需要**市值資料**，而
   `symbol_meta.sqlite` 沒有股本或市值。成交金額是流動性代理不是市值代理。**這是需要補的工具，
   在 `shioaji_stock_prices` 那一側。**
2. **產業鏈分類（`value_chain_classification.json`，47 條鏈、上中下游節點、2,212 檔多重歸屬）。**
   這是 `docs/en/research-objective.md` 從 cohort 研究以來一直想要的分組，本研究刻意沒用（見
   `mission.md` §1b）。它不會解決第 3 節的問題——更細的主題標籤還是等權重選中小型股——但它是
   一條**不同的**線：不是「哪十檔最強」，而是「哪一條產業鏈正在點火」。用它之前要記住兩件事：
   它是 **2026-08-23 的快照**（把今天的歸屬套到 2019 是輕微前視），而且**不在 worktree 的 data
   複本裡**。

以及一條已經量到、只是不符合本研究驗收門檻的線索：`skip_250_20` 的「同報酬、29% 週轉、2.67 倍
成交金額」值得在別的設計下再驗一次。
