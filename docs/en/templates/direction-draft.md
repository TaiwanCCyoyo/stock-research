# 方向草稿：待確認

> 這是方向草稿，不是研究結果。下列頭條的數字全部用 `▢` 佔位。流程見 [direction-drafts.md](../direction-drafts.md)。

討論在 GitHub draft PR，搭配 [PR 描述模板](direction-draft-pr.md)。手機直接看草稿與 PR
表格；假報告只在桌機 `preview/index.html` 預覽，不登錄 dashboard。
擁有者確認原話、假頭條與選擇前不得開始市場計算；代理核對確認者與版本後才回填連結。

## ① 擁有者原話目的與決定

原話：「待確認」（與 front matter 的 `owner_purpose` 相同）。

| 若答案…    | 擁有者能做的決定 |
| ---------- | ---------------- |
| 成立：     | 待確認           |
| 不成立：   | 待確認           |
| 分不出來： | 待確認           |

離最終目的還差哪幾步（本研究就是最終目的時寫「0 步」並說明理由）：

| 步驟 | 內容   | 本研究做不做      |
| ---- | ------ | ----------------- |
| 1    | 待確認 | 做 / 不做（理由） |

## ② 假頭條（按結果分支）

每個分支一行，以 `>` 開頭，數字一律用 `▢▢%`。

> 成立：待確認 ▢▢%。
> 不成立：待確認。
> 分不出來：待確認。

□ 這就是我要的（擁有者在 PR body 勾選；agreed 前抄入 `fake_headline_approved`）

若實際結果放不進三種形狀，必須先暫停頭條發布，用獨立 amendment PR 交給擁有者確認並
合併；不得自行換標籤。收尾在 `report.md` 的 `## 頭條發布確認` 記下形狀、結果證據與確認來源。

## ③ 報告骨架

3–5 個主面板；每個寫一句要說的話、用什麼圖、分母、期間，並標出主要或次要。

## ④ 條件 vs 結果圖例與白話定義

```text
           過去 ◀──────────── 今天 t0（起點 100 元）────────────▶ 未來
  【條件】往回看，用來挑股票                     【結果】往前看，要統計的事
  年均價 62.5 元 ──×1.6──▶ 100 元             100 元 ──×2──▶ 200 元（一年內曾收盤到）
  近一年低點 40 元 ──×2.5──▶ 100 元           100 元 ──×3──▶ 300 元 …
  寫法：「條件門檻 1.6 倍（相對年均價）」      寫法：「結果目標 2 倍（200 元）」
```

條件一律叫門檻並寫明基準；結果一律叫目標並同時寫出價格。「翻倍」只能指結果目標 2 倍。每個詞一句白話定義：

- 待確認
