# 研究方向討論採用互動介面

2026-11-02，PR #137 接手對話中，擁有者補充：

> 討論的介面，我不要都是冰冷冷的文字
>
> 比起冰冷冷文字，我更想要互動介面幫我理解跟溝通
>
> 這一個討論的 PR 修正，也想辦法在架構上，讓這點更能實現

這是本次直接收到的要求，修正 #137 前版把互動侷限為附屬桌機假報告的做法。
先前交接檔稱 D1–D6 已獲同意，但目前未獨立取得那六項決定的原始使用者確認；
交接敘述不作為個別研究批准證據，也不以 PR 描述反過來證明批准。
本紀錄只記這次可直接核對的互動需求；其他尚需 owner 確認的地方保留明示狀態。

## 分層與責任

| 層             | 做什麼                                              | 本 PR 的交付                               |
| -------------- | --------------------------------------------------- | ------------------------------------------ |
| 方向與來源     | `direction-draft.md` 保存原話、選擇、承諾與待解問題 | 保留既有草稿與確認閘門                     |
| 理解與探索     | 用選項比較、情境切換、按需展開，幫 owner 看懂差別   | 版本化共用 discussion kit 與可操作示例     |
| 回饋與確認     | 匯出同版本選擇／備註，代理回填並展示差異後，再確認  | proposed feedback 契約；不把點擊視為批准   |
| Dashboard 接入 | 顯示相同 model、重用 renderer、沿用回饋契約         | 後續接專用草稿入口；本 PR 不改正式報告索引 |

介面選擇取決於問題：簡單問答直接對話，關係用結構呈現，需要探索時主動提供互動。
互動不是裝飾；每個操作都必須讓使用者看見選擇會改變什麼，並能把想法帶回正式紀錄。
僅有這個 prompt 或一份規範還不夠，因此提供可重用實作、資料契約、authoring 指引與實際示例。

## 驗收與後續

- 同一個 renderer 能獨立開啟，也能在容器中 mount／destroy；不依賴市場 API。
- 三分支情境可切換，選項顯示差異，未解問題可展開，選擇與備註可匯出。
- 示範標示非研究結果；正式 view 必須指向實際草稿版本。沒有資料就明示未知。
- 任何操作都不改 `stage`、不批准計算、不改凍結草稿或研究結果。
- 後續 dashboard 工作實作專用 discovery／route／adapter，消費同一份模型；不得建立另一套批准狀態。
- PR #137 維持 draft，仍由擁有者決定 ready 與 merge。本紀錄不授權市場計算或部署。

實作與資料契約見 [互動討論介面](../direction-discussion-ui.md)。
